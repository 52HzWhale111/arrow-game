# 一箭又一箭（Arrow Out）· 基础版

一个用 **Python + Pygame** 写的点击式箭头解谜小游戏。这是课程作业"使用 Python 与 AIGC 开发小游戏"的**第一次提交**。

> 玩法参考微信小游戏《一箭又一箭》的核心思路，**没有使用原游戏的任何素材、代码或关卡**。
> 全部界面元素（箭头、爱心、按钮、图标、背景图案）都是用 Pygame 的绘图函数现场画出来的，
> 因此**项目不依赖任何外部图片/音频素材文件**。

---

## 一、游戏简介

棋盘上每个格子里最多有一个箭头，箭头有 **上 / 下 / 左 / 右** 四个方向。

点击一个箭头，程序会检查它**前进方向上、到棋盘边界之间还有没有别的箭头**：

- 前方 **没有阻挡** → 箭头飞出去并消失；
- 前方 **有阻挡** → 箭头不能消失，会**抖动、变红**并弹出"被挡住了！"的提示，同时 **扣掉一次失误机会**。

把本关箭头全部清空即可通关；失误次数（爱心）耗尽则本关失败，可以重新开始。

规则简单，但需要观察箭头之间的相互阻挡关系，想清楚**先点哪一个**——顺序不对就会白白浪费机会。

## 八、实现思路（关键代码在文件里都有中文注释）

### 1. 箭头和方向怎么表示

一个箭头只需要三个信息：**横坐标、纵坐标、方向**。方向用 `U/D/L/R` 四个字符表示，
格子坐标用 `(列, 行)`，和二维数组的下标一致。

```python
DIR_VEC = {"U": (0, -1), "D": (0, 1), "L": (-1, 0), "R": (1, 0)}   # 方向 -> 行列增量
```

关卡直接写成字符串数组，`.` 表示空格，这样一眼就能看出棋盘长什么样，也方便手工调整：

```python
{"name": "第 1 关", "grid": [".R.D",
                            "RU..",
                            "...L"]}
```

### 2. 路径检测（核心）

从箭头所在格出发，沿着它的方向一格一格往边界走。路上遇到任何一个"还活着"的箭头就说明被挡住了；
一路走出棋盘都没遇到，就说明可以飞出去。

```python
def blocked_by(self, arrow):
    dx, dy = arrow.vec                      # 该箭头的方向增量
    cx, cy = arrow.x + dx, arrow.y + dy     # 从它前面一格开始看
    while 0 <= cx < self.grid_w and 0 <= cy < self.grid_h:
        other = self.arrow_at(cx, cy)
        if other is not None:
            return other                    # 被这个箭头挡住了
        cx += dx
        cy += dy
    return None                             # 一路到边界都没东西 -> 可以飞出去
```

用 `while 0 <= cx < self.grid_w ...` 作为循环条件，边界情况天然就被处理掉了，
不会出现数组越界（测试用例 T03、T08 专门验证了这一点）。

### 3. 点击之后发生了什么

```python
def try_fly(self, arrow):
    blocker = self.blocked_by(arrow)
    if blocker is not None:
        # 被挡住：抖动 + 变红 + 提示文字 + 扣一次失误
    else:
        # 没被挡住：先做逻辑消除（alive=False），再放飞出的动画
```

关键的一点是 **先做逻辑消除、再播放动画**。这样箭头一飞出去就不会再挡住后面的箭头，
玩家可以连续快速点击，不用等动画播完。

### 4. 关卡是怎么保证一定能通关的

这是这个项目里最需要小心的地方：**随便撒箭头很容易撒出死局**。
比如 1×2 的棋盘上放 `→ ←`，两个箭头互相指着对方，谁也走不了，这一关就永远通不了关。

所以 `tools/gen_levels.py` 里用了 **逆推构造法**：

1. 从空棋盘开始，每次往一个空格里放一个箭头；
2. 放的时候要求：**它朝着自己方向到边界之间，没有任何已经放好的箭头**；
3. 重复到放满为止。

设放置顺序是 p1、p2、…、pn，那么 pn 放下去时它的射线是干净的，所以在完整棋盘里 **pn 一定能先飞走**；
它飞走之后棋盘回到 {p1…p(n-1)}，正好是 p(n-1) 放置时的样子，于是 **p(n-1) 也一定能飞走**……
以此类推，**按放置顺序的逆序点，一定可以通关**。构造的过程本身就证明了关卡有解。

生成的每一关还会再用程序验证一遍（`tools/gen_levels.py` 里的 `simulate()`），
`tools/test_game.py` 的 T07 更是直接让程序把 3 关全部自动通关一次。
`tools/levels_out.txt` 里保存了每一关的参考解法，方便自己试玩时对照。

### 5. 箭头是怎么画出来的

参考图里的箭头是"粗圆头的箭杆 + 大三角箭头，箭尾逐渐变淡"。
做法是先在透明蒙版上画出整支箭头的白色剪影，再和一张横向的透明度渐变图做
`BLEND_RGBA_MULT` 相乘，最后用同样的方式染上颜色：

```python
mask.blit(grad, (0, 0), special_flags=pygame.BLEND_RGBA_MULT)   # 让剪影带上渐变透明度
tint.fill(color + (255,))
tint.blit(mask, (0, 0), special_flags=pygame.BLEND_RGBA_MULT)   # 染成目标颜色
```

整支箭只在第一次用到时算一次，之后按 `(格子大小, 方向, 颜色)` 缓存，四个方向靠旋转得到。
